# 運用手順

1〜6 は 1 台の PC で管理者 1 人が使うとき(ローカル版)の手順。データはこの PC の Chrome の中にだけ保存されます。
複数人・複数端末で使うときは 7(共有版)。

## 1. 起動する

- フォルダの `起動.command` をダブルクリックする(簡易サーバーを立ち上げて Chrome で開く)
- 2 回目からは Chrome のブックマーク http://localhost:8080/ でも開けるが、PC を再起動した後は `起動.command` を先に実行する
- アプリらしく使うなら: Chrome のアドレスバー右端の「インストール」ボタン(または ⋮ → 保存して共有 → アプリをインストール)。Dock から単独ウィンドウで開けるようになる。この場合も PC 再起動後は `起動.command` が必要

初めて開くとき、`起動.command` が「開発元を確認できない」と止まったら、右クリック → 開く で許可する。

## 2. 最初の設定(1 回だけ)

設定画面で次を入れる。

1. 会社名
2. チーム(駐車場ビューの区画になる)。不要な「本社」は × で消す
3. 整備の種別(足りないものを追加)
4. アラートの日数(既定: 30 日以内は赤、60 日以内は黄)

サンプルデータが入っていたら、設定 →「すべて削除」で消してから始める。

## 3. 車両を一括登録する

1. 設定 →「車両を CSV で一括登録」→「テンプレート」でひな形を保存
2. Excel で開き、2 行目の例を消して、1 行 1 台で入力。必須は「ドライバー名」と「ナンバー」だけ。ほかは空欄でよい
   - 日付は `2027/3/31` の形でよい(`R9.3.31`、`20270331` も読める)
   - ステータスは 稼働中 / 修理中 / 休車 / 廃車 のどれか。空欄は稼働中
   - チームは設定で登録した名前と同じ文字にする
3. CSV(UTF-8)で保存。Excel では「CSV UTF-8(コンマ区切り)」を選ぶ
4. 設定 →「読み込む」(または車両台帳の「CSV 読み込み」)で選ぶと、登録前に内容の一覧と問題点が出る。問題があれば直して読み込み直す
5. 同じナンバーの車両があれば上書きになる。空欄の項目は今の値を残す(車検日だけ更新、などに使える)

## 4. 日々の入力

| いつ | どこで | 何を |
|---|---|---|
| 異常・傷を見つけた日 | 車両詳細 →「異常を登録」 | 場所 → 左右前後 → 図をクリック。写真を撮っておく。事故なら「事故記録として残す」にチェック |
| 修理・整備が終わった日(請求書が来た日) | 整備記録 →「整備を記録」 | 種別・費用・走行距離・次回の目安。車検は「車検」種別で記録すると満了日が台帳に入る |
| 車を修理に出した日 | 車両の編集 → ステータス「修理中」 | 代車があれば代車欄に入れる。戻ったら詳細の「代車を返却して稼働に戻す」 |
| 月初 | ダッシュボード | 要対応・注意の件数を見て、車検・保険の手配を進める |

## 5. バックアップ(週 1 回・必須)

- ダッシュボードに黄色の「バックアップを書き出してください」が出たら、ボタンを押す(7 日以上空くと出る)
- `車両管理バックアップ_日付.json` がダウンロードに入るので、会社の共有フォルダか外付けディスクに移す。写真も入っている
- 復元: 設定 →「バックアップを読み込む」。別の PC に移すときも同じ
- Chrome の「閲覧履歴データの削除」で「Cookie と他のサイトデータ」を消すとアプリのデータも消えるので注意。消してしまったらバックアップから戻す

## 6. 困ったとき

- 画面が古いまま: Cmd + Shift + R で再読み込み
- 「このサイトにアクセスできません」: サーバーが止まっている。`起動.command` をもう一度実行
- 入れた覚えのない車両が並ぶ: サンプルデータが入っている。設定 →「すべて削除」

## 7. 複数人で共有する(共有版)

共有版では、データをクラウド(Supabase)に置き、ログインした人全員が同じ内容を見ます。誰かが入力すると、他の人の画面にもすぐ反映されます。写真もクラウドに保存されます。1〜6 の使い方は同じで、違いは「起動のしかた」と「ログインがあること」だけです。

### 7-1. Supabase の用意(管理者が 1 回だけ、15 分)

1. https://supabase.com にログインし、New project。名前は `fleet-manager`、Region は `Northeast Asia (Tokyo)`。データベースのパスワードは控えておく(アプリでは使わない)
2. 左メニュー SQL Editor → New query → このフォルダの `supabase/schema.sql` の中身を全部貼り付けて Run。「Success」と出れば OK(テーブル 4 つ、権限、写真置き場ができる)
3. 左メニュー Authentication → Sign In / Providers → Email で **「Allow new users to sign up」を OFF**(勝手に登録されないように)。同じ画面の「Confirm email」も OFF にすると、追加した人がすぐログインできる
4. Authentication → Users → **Add user → Create new user** で、使う人のメールアドレスとパスワードを登録する(「Auto Confirm User」にチェック)。人数分くり返す
5. Project Settings → API Keys で **Project URL** と **publishable key**(`sb_publishable_...`。古い画面では anon key)をコピーする。`sb_secret_...` や service_role は絶対に使わない
6. Authentication → URL Configuration の Site URL に `https://mnt22914-a11y.github.io/fleet-manager/` を入れ、Redirect URLs にも同じ URL と `http://localhost:8080/` を足す。「パスワードを忘れた」のメールのリンク先になる

### 7-2. アプリに設定を入れる

`js/config.js` を開き、5 でコピーした 2 つを貼る。

```js
window.FLEET_CONFIG = {
  SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
  SUPABASE_ANON_KEY: 'sb_publishable_xxxxxxxx',
};
```

空のままならローカル版(このブラウザだけ)のまま動く。入れると次に開いたときからログイン画面になる。

### 7-3. 今あるデータを共有版に移す

1. ローカル版のまま、設定 →「バックアップを書き出す」で JSON を保存
2. `js/config.js` に設定を入れて開き直し、ログイン
3. 設定 →「バックアップを読み込む」で 1 の JSON を選ぶ。写真も一緒に移る

### 7-4. 公開(インターネットのどこからでも開けるように)

公開 URL: **https://mnt22914-a11y.github.io/fleet-manager/**(GitHub Pages、リポジトリ https://github.com/mnt22914-a11y/fleet-manager の main ブランチをそのまま配信。2026-10-23 公開)。
Chrome で開いて「インストール」すればアプリとして使える。スマホでも開ける。コードを直して `git push` すると 1〜2 分で公開側も更新される。
`js/config.js` のキーは公開されるが、それは「公開用」のキーで、ログインしていない人は何も読めない(schema.sql の RLS で守っている)。

### 7-5. 共有版での毎日

- 開く → ログイン(一度ログインすればしばらく覚えている)
- 入力のしかたは 4 と同じ。保存は自動。保存に失敗すると右下に赤く出るので、電波を確認してもう一度
- 利用者を増やす・減らす: Supabase の Authentication → Users で追加・削除
- パスワードを変える: 設定 → アカウント →「変更」。忘れたらログイン画面の「パスワードを忘れた」でメールが届く(7-1 の 6 を設定しておくこと)
- バックアップ: 月に 1 回は設定 →「バックアップを書き出す」で手元にも残す。「すべて削除」「サンプルデータを入れる」「バックアップを読み込む」は**全員のデータが変わる**ので、共有版では管理者だけが使う

### 7-6. 困ったとき(共有版)

- ログイン画面で「メールアドレスかパスワードが違います」: Supabase の Users に登録されているか、メールが確認済み(Confirmed)かを管理者が見る
- 「読み込みに失敗しました」: `js/config.js` の URL とキー、SQL を Run したかを確認
- 写真が出ない: 少し待つ(署名付きの URL を取りに行っている)。それでも出なければ schema.sql の写真の部分(storage)を Run し直す
- 他の人の変更が反映されない: 画面を再読み込み。続くなら Supabase の Database → Publications で supabase_realtime に 4 テーブルが入っているか見る
