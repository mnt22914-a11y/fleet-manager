## 3D モデルについて(いちばん手が入っている所)

- 本体は `js/van3d.js`。Three.js r128(cdnjs)+ GLTFLoader(jsdelivr)を `index.html` で読む
- 手作りモデル: 側面シルエットを押し出した車体 + 貼り付けパネル。寸法と配置は `reference/` の三面図と `reference/3d-spec.md` に合わせてある
  - 寸法は `DIM`、部位ごとの範囲は `REGIONS`、車体本体をタップしたときの部位判定は `partFromPoint()`
  - 異常のある部位は赤(メッシュの色替え)、選択は青い縁取り。メッシュのない部位(電装など)は範囲ボックス
- 実車 GLB への切り替え: `models/van.glb` を置くと自動でそちらを使う(`models/README.md`)。向きは `models/van.json` で調整
- `tests/` には 3D のテストはない。ヘッドレス Chrome で描画して目で見る(下記)

## やりかけ: Blender スクリプトから GLB を作って組み込む

1. `brew install --cask blender` を実行中(2026-10-18 時点で未完了。`/Applications/Blender.app` が無ければ再実行)
2. 生成: `cd tools && /Applications/Blender.app/Contents/MacOS/Blender -b -P build_realistic_kei_van.py`
   - `tools/kei_van_realistic.glb` と `.blend` ができる(スクリプトは相対パスに保存する)
3. `cp tools/kei_van_realistic.glb models/van.glb`
4. 向き合わせ: スクリプトは Blender 座標で +X が前。glTF 書き出しで Y-up になり、前は +X のまま。
   van3d.js は長手を自動で z に回す(+x → -z になる)ので、`models/van.json` に `{ "front": "-z" }` を書いて前を +z に向ける。見て逆なら `"+z"` に
5. ブラウザで車両詳細を開き、ドアや前後の位置が REGIONS の赤い箱と合うか確認。ずれていれば REGIONS か van.json の scale / rotationY を直す
6. 問題なければ `models/van.glb` と `van.json` をコミット(glb は数 MB 想定)

## 動作確認のやり方(ヘッドレス Chrome)

家計簿アプリの `tests/cdp.mjs` を流用した手順。概要:

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --remote-debugging-port=9333 \
  --user-data-dir=/tmp/chrome-prof --window-size=1440,1000 \
  --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader \
  http://localhost:8080/ &
# あとは CDP(Page.captureScreenshot / Runtime.evaluate)で画面を撮る
# 3D の視点は window.__van3dView = { yaw, pitch, radius } で指定できる
```
