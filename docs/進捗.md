## 車体の図(2D・5 面、図面画像をそのまま使用)

- 2026-10-19 に 3D(Three.js / Blender)をいったんやめ、2D の 5 面図(左側面・右側面・上面・正面・背面)にした。3D のコードは git 履歴(コミット 5bc6b75 まで)に残っている
- 図は reference/ の図面画像を切り出した `img/side.jpg`・`front.jpg`・`rear.jpg`・`top.jpg`(top は前が上になるよう 90° 回転)。左側面は side.jpg を左右反転して使う
- img/ は `python3 tools/clean_blueprints.py` で生成する(車の外側を白に、方眼を除去、寸法線・引き出し線・窓の中の注記を個別に消す)。消す線の座標はスクリプト内に直書き。直すときは座標格子付きの画像を書き出して読む(スクリプト末尾のコメント参照)
- その上に透明な部位の領域を重ねる。領域の座標(画像ピクセル)は `js/regions2d.js`。描画は `js/views2d.js`
  - 領域を直すときは、元の表示座標(2000 幅の画像での座標)で考えて python で変換するのが楽。変換式: 元画像 = 表示 × 1.408、クロップ枠を引く、top は (x, y) → (H − y, x)、最後に縮小率を掛ける(side のみ 0.677)
  - 側面の領域は wheel_f / wheel_r / mirror / side / lamp_f / lamp_r という汎用 ID で、左右に応じて _l / _r を付ける
  - ランプは 2026-10-19 に左右前後 4 部位(lamp_fl / fr / rl / rr)に分けた。旧 'lights' の記録は store.normalize で「その他」に移る
- 部位の一覧は `js/logic.js` の PARTS(`onBody: false` の部位は図の下のチップで表す)
- 異常の登録は「場所(PART_GROUPS)→ 左右前後 → 図の上をクリックしてピン」の 3 段(app.js の attachPartPicker)。ピンは issue.pin = { view, x, y }(面のキーと 0〜1 の相対位置)
- 異常のある部位は赤の半透明、ピンのある異常は番号付きのピン、ピンのない異常は部位の中央に件数の印。選択中は青枠。面ごとに「異常 n 件」を見出しに出す。`.view-img.debug` を付けると全領域が見える(位置合わせの確認用)

## 2026-10-23 共有版(本人の指示「共有して使えるようにしよう」)

- 保存層を 2 本にした。`js/store.js` はメモリ上の state を持ち、操作 → state 更新 → 購読者に通知 → 後ろで backend に書く(書き込みは queue で順番を守る。失敗は store.onError → 右下の赤いトースト)。backend は `js/backend-local.js`(localStorage に全体 1 JSON、以前と同じ KEY `fleet.v1`)と `js/backend-supabase.js`
- 切り替えは `js/config.js`(window.FLEET_CONFIG)。空ならローカル、URL とキーがあればクラウド。index.html で app.js より先に読む
- Supabase 側: `supabase/schema.sql`。vehicles / records / issues / settings の 4 テーブルはすべて `{ id text, data jsonb, updated_at }`(アプリの形をそのまま jsonb に入れる。列を増やさずに済む)。RLS は「authenticated なら全部 OK、anon は何もできない」の 1 社運用。10/30 以降の Supabase の仕様(新テーブルは明示 grant が必要)に合わせて grant を書いてある。Realtime は 4 テーブルを publication に追加。写真は非公開バケット photos(`<id>.jpg`)
- 他の端末の変更: backend.onChange(postgres_changes) → `logic.applyRemoteChange`(純粋関数、テストあり)。ローカルの updatedAt のほうが新しければ上書きしない
- 写真(`js/photos.js`): クラウドでは署名付き URL(12 時間)を state に出てくる ID 分まとめて取る(`ensure`)。新しい ID が来たら取って再描画(setOnLoaded)。アップロードは `upload(upsert)`、バックアップの書き出しは download で全部読む
- 画面: ログイン画面(メール + パスワード、「パスワードを忘れた」= resetPasswordForEmail)、サイドバー下にモードとメール + ログアウト、設定に「アカウント」カード(パスワード変更)。PASSWORD_RECOVERY イベントで新パスワードのダイアログ。共有モードでは「すべて削除 / サンプル / バックアップ読み込み」の確認文を「全員に影響」に変えた
- 利用者の追加はアプリからはできない(Supabase の Authentication → Users で管理者が Add user)。Sign up は OFF にする手順を運用手順 7 章に書いた
- 確認したこと: ローカルモードでサンプル投入・追加・削除・再起動後の永続(ヘッドレス Chrome は kill でなく Browser.close で閉じないと localStorage が flush されない)、偽の URL でログイン画面が出ること。本物の Supabase(プロジェクト gjwjqbxzmvudawzxswpn、2026-10-23 本人が作成)でも通し確認済み: ログイン → サンプル投入 → 別タブに Realtime で即時反映 → 写真アップロードと署名付き URL で表示 → バックアップ書き出しに写真が含まれる → 削除の反映 → 未ログインの REST は 401。確認スクリプトは scratchpad の cloud-test.mjs(2 タブを CDP で操作)

## 2026-10-23 スマホ入力の修正(本人の指示「スマホ入力がバグってるから確認と修正」)

- 原因と直したもの:
  - 検索欄に 1 文字打つたびに render() で画面全体を作り直し、focus() で戻していた → スマホではキーボードが閉じる・カーソルが飛ぶ。`renderResultsOnly()` で結果(`[data-results]`)と件数だけ差し替えるようにした
  - 共有モードで他端末の変更が来ると入力中でも作り直していた → `typingInApp()` の間は `deferRender()` で後回し(400ms ごとに見て、入力から抜けたら描く。focusout はヘッドレスでは飛ばないので使わない)
  - 入力欄の文字が 14px → iOS が拡大してしまう。≤860px では input/select/textarea を 16px に
  - ダイアログはスマホでは下から出るシート(幅 100vw、`100dvh` 基準、フッターを sticky)。開いている間は body をスクロールさせない。スマホでは自動フォーカスしない(キーボードが勝手に出て跳ぶ)
  - 設定の `.grid-2` が 860px 以下でも 2 列のまま右にはみ出していた → 1 列に。`.settings-row` も縦積み
  - 図の hover 色はマウスのある端末だけ(`@media (hover: hover)`)。タッチで押した色が残らない
- 確認: Emulation.setDeviceMetricsOverride(390x844, mobile, touch)で、検索中のフォーカス維持・結果差し替え、後回し再描画、シート表示、図のタップでピン、設定のはみ出し 0 を確認(scratchpad の mobile2.mjs / dbg.mjs)
- backend-supabase.isMember(): `is_member` 関数が無い(02_signup.sql 未適用)なら true を返す。これで SQL を Run する前に push しても壊れない

